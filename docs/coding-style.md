# Coding Style

Consistency matters more than any single rule. Match the surrounding code.
Formatting is enforced by `rustfmt`; lints by `clippy`.

## Rust

- **Edition:** 2021, `no_std` throughout. Host-only test/tooling crates may use
  `std`.
- **Formatting:** `cargo fmt`. CI runs `cargo fmt --check`.
- **Lints:** `cargo clippy --all-targets -- -D warnings` must pass. Crates
  additionally set:
  ```rust
  #![no_std]
  #![forbid(unsafe_code)]        // except the `hal` crate — see ADR 0007
  #![deny(missing_docs)]         // on public kernel/server APIs
  ```
- **Naming:** standard Rust — `snake_case` items, `CamelCase` types,
  `SCREAMING_SNAKE_CASE` consts. No Hungarian notation.
- **Errors:** return `Result<T, E>` with explicit error enums. No `unwrap()` /
  `expect()` in kernel or server code paths that can fail at runtime; reserve
  panics for genuine invariant violations. `panic!` in the kernel halts;
  servers are restartable.
- **Integer/hardware types:** fixed-width (`u64`, `u32`). Use `bitflags` or
  typed newtypes for register fields, never bare integers passed around.
- **No `as` casts** where `From`/`TryFrom` works; `as` only for deliberate,
  commented truncation.

## The `unsafe` rule (critical)

`unsafe` is **forbidden** everywhere except the `hal` crate. See
[ADR 0007](adr/0007-unsafe-policy.md). In `hal`, every `unsafe` block is as
small as possible and is immediately preceded by a `// SAFETY:` comment stating
the invariant that makes it sound:

```rust
// SAFETY: COM1 base port 0x3F8 is fixed on PC-compatible hardware and this
// driver holds the only handle to it, so no aliasing write can occur.
unsafe { Port::new(0x3F8).write(byte); }
```

A `// SAFETY:` comment that does not actually justify the invariant is a bug.

## Hardware structures

Use `#[repr(C)]` / `#[repr(packed)]` and assert layout:

```rust
#[repr(C)]
struct GdtEntry { /* ... */ }
const _: () = assert!(core::mem::size_of::<GdtEntry>() == 8);
```

## Comments & specs

Explain *why*, not *what*. When code implements hardware behaviour, cite the
manual: `// Intel SDM Vol. 3A §6.14.2: the IST mechanism`.

## Assembly

Prefer Rust with `core::arch::asm!`. Standalone `.s`/`.S` files only when
unavoidable (e.g. the ring-3 trampoline), documented with calling convention
and clobbers.

## Commits

[Conventional Commits](https://www.conventionalcommits.org/) with a crate /
subsystem scope:

```
feat(cap): add capability derivation with right attenuation
fix(hal/idt): use IST1 for the double-fault handler
docs(adr): record the capability security model
chore(ci): run cargo deny on every PR
```

Types: `feat`, `fix`, `docs`, `refactor`, `test`, `build`, `ci`, `perf`, `chore`.

> Do **not** add co-author or "generated by" trailers of any kind to commits
> or PRs.
